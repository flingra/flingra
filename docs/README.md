# Documentation

Use this directory for product-level documentation and decisions that apply to both applications.

## Start here

- [System blueprint](architecture.md): product scope, proposed architecture, delivery sequence, and cross-cutting security requirements.
- [Frontend guide](../frontend/README.md): web client implementation and testing conventions.
- [Backend guide](../backend/README.md): API, data, authentication, and integration conventions.
- [Frontend build roadmap (PDF)](frontend-roadmap.pdf): phased implementation map and backend handoffs.
- [Backend build roadmap (PDF)](backend-roadmap.pdf): phased Go API implementation map and frontend handoffs.

Record significant decisions in short Architecture Decision Records (ADRs) when they cannot be adequately captured in the relevant guide. An ADR should state the context, decision, alternatives considered, and consequences. Avoid documenting speculative implementation details as settled decisions.
