Flingra · Delivery map · Frontend

What to build next

A phased build path for the React + TypeScript web client, with backend handoffs and safety checkpoints.

Product direction: Build one shared Flingra app for all eligible adults. A member's identity does not determine whom they want to discover or who may discover them. Preferences stay private unless the member chooses to publish an identity field.

Current state: scaffold only Routes and APIs below are targets, not implemented features. Follow the detailed field and behavior rules in frontend/README.md.

Build sequence

0 · Align contract and unblock development

  • Confirm signup identifier, age eligibility, contact verification, profile fields, photo rules, and the discovery audience vocabulary with product/backend.
  • Agree API origin, cookie domain/SameSite strategy, CSRF header, CORS origins, error envelope, and OpenAPI workflow.
  • Bootstrap Vite + React + TypeScript, Router, accessible app shell, lint/type-check/test commands, and environment config.

Done when: frontend and backend can run locally, and both teams use the same reviewed API contract.

1 · App foundation and account access

  • Public routes: landing, sign up, sign in, contact verification, forgot/reset password, terms/privacy/safety.
  • Typed API client; cookie credentials; CSRF header for mutations; global session state and protected-route UX.
  • Field validation, generic auth/recovery errors, rate-limit/network states, accessible forms.

Backend handoff: auth endpoints, cookie and CSRF behavior, account state, stable error codes, resend/expiry limits.

Done when: signup → verification (if required) → sign-in/session and recovery flows pass end-to-end.

2 · Onboarding and own profile

  • Step-based onboarding for minimum basic profile and approved optional fields; show visibility beside sensitive choices.
  • Separate private discovery preferences (“who I want to see”) from visibility preferences (“who can see me”).
  • Profile preview, edit/save, settings/security, and deletion-request UI once backend policy is defined.
  • Defer photo upload UI until storage, file limits, moderation states, and upload contract are ready.

Backend handoff: `/me`, profile read/update, preference read/update, account state, approved field enums and validation limits.

Done when: a member can save, resume, and preview their profile without leaking private fields.

3 · Discovery and safety core

  • Discovery cards, profile details, bounded filters, pagination, empty/error/retry states.
  • Ask for location only in context; handle denial and approved coarse/manual fallback.
  • Block/unblock, report form, blocked list, safety/help content; make safety actions reachable from profiles.

Backend handoff: server-filtered compatible candidates, public profile DTO, block/report endpoints, reason list, cursor behavior.

Done when: browser never receives an incompatible profile or exact/private location; reporting/blocking behavior is verified.

4 · Quality, accessibility, and launch readiness

  • Playwright core journeys: signup, recovery, onboarding, edit, location denied, report/block, session expiry, account deletion request.
  • Test mobile layouts, keyboard/screen-reader behavior, focus handling, low bandwidth, stale cache clearing, and error recovery.
  • Check CSP/deployment headers, remove sensitive analytics, and ensure logs/screenshots/traces contain no real personal data.

Done when: core acceptance criteria in the frontend specification pass against a staging API.

Keep out of the first build

Messaging, payments, identity verification, push notifications, calls, and staff moderation UI are later modules. Do not start these until product scope, safety operations, provider contracts, data retention, and backend endpoints are approved.

Next actions

  1. Frontend and backend review the API contract and resolve product decisions.
  2. Bootstrap the client shell and typed API plumbing while backend creates the first OpenAPI/auth slice.
  3. Integrate incrementally by vertical slice: auth, profile/preferences, discovery, then safety.
