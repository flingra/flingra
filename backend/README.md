# Backend

The API and domain services will live in this directory. The repository is currently a scaffold; this guide describes the proposed starting point, not an implemented service.

See the [system blueprint](../docs/architecture.md) for shared product and security requirements.

## Proposed baseline

- FastAPI and Pydantic for HTTP APIs and request/response validation.
- MySQL 8.4 LTS as the primary relational store; SQLAlchemy for persistence and Alembic for reviewed schema migrations.
- Pytest for unit, integration, and API tests.
- OpenAPI generated by FastAPI as the API contract.
- Docker for repeatable local and CI environments.

Start with a modular monolith: one deployable API with clear feature/domain boundaries. Do not split into microservices until a measurable scaling or ownership need justifies the operational cost.

Use Redis, Celery, WebSockets, and external services only when a concrete use case requires them. Define timeouts, retry limits, idempotency, and failure behavior for each asynchronous or external operation.

## API and data conventions

- Version and document public API changes. Validate all untrusted input at the API boundary and enforce authorization in the domain/service layer for every protected operation.
- Use explicit response schemas; do not serialize ORM models or internal fields directly.
- Use parameterized ORM queries. Apply pagination and bounded result sizes to collection endpoints.
- Store timestamps consistently in UTC and make migration changes reviewable and reversible where practical.
- Keep database credentials and provider secrets in a managed secret store or environment injection, never in source control.
- Return stable, non-sensitive error responses. Log a correlation/request ID and operational context, but not passwords, tokens, payment details, precise location, or message contents.

## Authentication and sensitive data

- Hash passwords with Argon2id using a maintained library and its recommended parameters.
- For browser sessions, prefer short-lived access credentials and rotated, revocable refresh sessions in `Secure`, `HttpOnly`, appropriately `SameSite` cookies; apply CSRF protection to cookie-authenticated state-changing requests. Avoid storing bearer tokens in browser storage.
- Rate-limit sign-in, OTP, password reset, and other abuse-prone endpoints. Use generic account-recovery responses to reduce account enumeration.
- Collect the minimum personal data needed. Restrict staff access, define retention and deletion behavior, and avoid logging sensitive values.
- Never store payment card data. Verify payment-provider webhook signatures, enforce idempotency, and reconcile provider events before changing payment state.
- Treat identity verification as a sensitive third-party integration: minimize retained evidence and document access, retention, and deletion rules before launch.

## Integrations and operational readiness

Wrap payment, SMS/OTP, push, maps, storage, and real-time providers behind narrow adapters. Handle provider timeouts and outages explicitly; do not report a payment, verification, or message as successful until confirmed.

Before production, define health checks, structured redacted logs, error monitoring, backups and restore tests, database migration procedures, and an incident contact/escalation path. Protect admin and moderation operations with least-privilege access and audit trails.

## Testing

- Unit-test domain rules and authorization decisions.
- Integration-test migrations and persistence against a real test database where feasible.
- Test API validation, unauthenticated access, forbidden access, rate limits, and provider webhook verification.
- Use synthetic fixtures; never copy production personal data into local or CI environments.

## Local development

There is no backend application or dependency manifest yet. When bootstrapping, document the supported Python version and exact environment setup, migration, run, lint/type-check, and test commands here. Keep local secrets in an ignored environment file and provide only a placeholder `.env.example`.
